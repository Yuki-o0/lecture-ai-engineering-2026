# 第3回 解答

## 演習

- 第1回（素のLLM）とエージェントの回答の違い：エージェントの回答では、glossary.jsonを引用して関係する回も含む回答が生成された。
- `--trace` で見えたツール呼び出し（ツール名と引数）：ツールコールは2回
    ツール名: search_glossary
    引数: {'query': 'LoRA'}
    ツール名: search_glossary
    引数: {'query': 'QLoRA'}
- 1つの質問での LLM 呼び出し回数（`requests`）：2回。質問（"LoRA とQLoRAの違いは？"）をLLMに送信し、ツール（search_glossary）の実行要求を返すステップと、プログラム側で実際にツールを実行して得られた結果（JSONデータ）をLLMに渡し、その情報をもとに最終的な回答テキストを生成させるステップ。
- 追加したツールと、docstring に書いた説明：指定した回の用語から1つを選び、確認問題と答えを返す。
「第2回の確認問題を出して」のように、復習用のクイズや問題を求められたときに使う。

## 宿題

- 取り組んだレベル：実装
- やったこと：学習の記録を learning_log/ フォルダに安全に保存するツール save_learning_log を作成した。保存処理の直前にユーザーの承認を求めるヒューマンインザループの仕組みを実装した。CLI上で「この内容を保存しますか？ [y/n]:」と確認し、ユーザーが保存を拒否した場合、AIに「拒否された」という結果を返して対応を任せるのではなく、プログラム側（if denied: return None）で即座に処理を打ち切るようにした。
- 結果：「y」を入力すると、ツールが実行されて学習記録が保存され、LLMからは「保存しました」という完了報告と要約内容に対するポジティブなフィードバックが返された。「n」を入力すると、保存処理はキャンセルされた。当初、LLM側は保存されなかったという結果を受け取り、保存しなくてよかったのか再確認するような応答を生成したため、CLI側で「学習記録の保存をキャンセルしました。」と表示し、即座に処理を終了するように修正した。
- 気づき・疑問：保存前に利用者の確認を挟むことを確認できた。ツールの実行拒否時のハンドリングをすべてAIに任せると、不要な対話が続くことがあるため、拒否時はCLIで制御を打ち切ることで、UXが大きく向上することがわかった。ヒューマンインザループでは、「AIにどう応答させるか」だけでなく、「どのタイミングでAIへのリクエストを止めるか」というアプリケーション側の設計も非常に重要であると感じた。
